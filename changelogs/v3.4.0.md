# monSQLize v3.4.0

> Release date: 2026-10-27
> Publication authority: the immutable tag and npm registry. An untagged checkout is a release candidate; the date above does not establish registry availability.

## Highlights

Minor release. Adds the Search index lifecycle API on collection accessors and Models for full-text `search` and `vectorSearch` indexes. Existing APIs, defaults and dependency versions are unchanged. Node.js `>=18` remains the consumer runtime.

## Added

- Search index lifecycle API: `createSearchIndex`, `createSearchIndexes`, `listSearchIndexes`, `getSearchIndex`, `updateSearchIndex`, `dropSearchIndex`, and `waitForSearchIndex`. Write methods follow `writePathPolicy` as `management` operations.
- `SearchIndexInfo` reports `typeSource` (`server` / `inferred` / `unknown`) and infers the type from the definition when the server omits a top-level `type` (self-managed mongot).
- Six error codes: `INVALID_SEARCH_INDEX_DEFINITION`, `SEARCH_INDEX_EXISTS`, `SEARCH_INDEX_NOT_FOUND`, `SEARCH_INDEX_UNSUPPORTED`, `SEARCH_INDEX_BUILD_FAILED`, `SEARCH_INDEX_WAIT_TIMEOUT`.
- Opt-in real-environment check: `npm run test:search-index:real` against `mongodb-atlas-local`.

## Behavior notes

- Whether a `vectorSearch` index can be updated in place depends on the deployment: rejected on `mongodb-atlas-local` (mongod 8.3.13); accepted on Community 8.2.12 with mongot; Atlas cloud not tested by this release. monSQLize passes server rejections through as `MONGODB_ERROR` with `serverCode` and does not fall back automatically. Docs describe a zero-downtime rename-and-switch pattern and a drop-then-recreate option when brief downtime is acceptable.

## Budgets

- Root CJS/ESM bundle budgets rise from 820,000 to 840,000 bytes per artifact; the CLI budget stays 50,000 bytes.
- Documentation site single JavaScript file budget rises from 700,000 to 720,000 bytes for the new Search index page.

## Upgrade and rollback

No migration is required for existing APIs. New Search index methods are additive. Rollback to 3.3.4 removes the Search index lifecycle API and restores the previous root/site bundle budgets.
