# monSQLize v3.5.0

> Release date: 2026-10-27
> Publication authority: the immutable tag and npm registry. An untagged checkout is a release candidate; the date above does not establish registry availability.

## Highlights

Minor release. Adds GridFS buckets on `msq.gridfs()` and `model.gridfs()`. Existing APIs, defaults and dependency versions are unchanged. Node.js `>=18` remains the consumer runtime.

## Added

- GridFS buckets: upload, download, byte ranges, `getFile`, `findFiles`, delete/drop, and a formal `ensureIndexes` method. `contentType` is stored in `metadata.contentType` (compatible with MongoDB Driver 6.x and 7.x).
- Phase-1 resumable upload: start, append chunks, finalize and abort. Upload sessions expire through a 7-day TTL index that does not cascade to already written chunks.
- `writePathPolicy` gains a `gridfs` field and category. Under model-only with inherit, GridFS reads stay allowed and writes require `gridfs: 'allow'`; `drop` is a management operation. Violations stay `INVALID_OPERATION` with `reason: 'WRITE_PATH_POLICY'`. Matching receives the collection-style internal instance id (`iid`).
- Six `GRIDFS_*` error codes. Driver failures from `getFile`, `findFiles`, `abortResumableUpload` and index creation map to `MONGODB_ERROR`, with the driver error kept as `cause`.

## Budgets

- Root CJS runtime budget rises to 874,000 bytes and ESM to 871,000 bytes; `gridfs()` stays synchronous, so the single-file build keeps GridFS in the main bundle. The CLI budget stays 50,000 bytes.

## Upgrade and rollback

No migration is required for existing APIs. GridFS methods are additive. Rollback to 3.4.0 removes the GridFS API and restores the previous bundle budgets; GridFS collections already written remain readable through the native driver.
