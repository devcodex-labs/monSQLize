# monSQLize v3.3.2

> Release date: 2026-10-22
> Publication authority: the immutable tag and npm registry. An untagged checkout is a release candidate; the date above does not establish registry availability.

## Highlights

This patch consolidates the audited fixes after 3.3.1 for BSON query identity, cache invalidation, Model visibility and writes, pagination, transactions, Change Stream sync and resource cleanup. Public entry points, Node.js `>=18`, direct production dependencies and build formats remain unchanged. Release and docs tooling require Node.js 22.

## Fixed

- Isolate query, page, totals and bookmark caches by data source, authentication identity and pool. Link same-source route invalidation and fence stale in-flight reads and backfills across writes, commits and received invalidation.
- Preserve effective BSON input and decoding options, ordered document/Map values, undefined, negative zero, binary views and subtypes, inherited BSON settings and cross-realm leaves in shared query identities. Capture functions per native occurrence and preserve Code scope access. Avoid JSON result caching for incompatible result modes or lazy dynamic decoding maps.
- Align explicit Model aggregate/page invalidation with soft-delete visibility, converted filters and captured execution pipelines. Isolate malformed invalidation descriptors so valid siblings still run; successful writes keep their native results. Automatic invalidation stays off by default, and post-write/post-commit invalidation remains best-effort.
- Apply supported page projections after custom pipeline stages; reject write stages and unsupported find-only projections. Preserve requested ID order in one native query for supported excluded/computed `_id` projections; reject combinations that cannot retain the original identity. Honor native MongoDB equality, collation and sorting during populate, with documented query-cost boundaries.
- Preserve schema factory captures, lexical bindings, comments and every ECMAScript line terminator. Correct nested DSL scopes and literals without reinterpreting prepared data. Retain Model business filters through final hooks and atomic writes, strict conflict classification, ID-only projections and soft-delete timestamps.
- Serialize transaction commit/abort/end, apply work deadlines before commit, and conservatively invalidate uncertain commit results without automatically replaying application callbacks. Invalidate after partial batch writes and report only confirmed inserts.
- Persist an initial Change Stream operation-time checkpoint before opening an empty-store stream; retain raw-token compatibility, strict failure barriers and target-name uniqueness. Use unambiguous per-target idempotency keys and retry failed owned-resource cleanup without losing ownership.
- Keep slow-log initialization, queues and diagnostic failures isolated, drain admitted work on close and retain event-time bounds. Preserve remote TTL/tag capabilities and shared L1 invalidation fences. Correct CountQueue handoff, pool startup/close/health/statistics, retryable cleanup, Logger tracing and Data Task compare-and-swap boundaries.
- Repair bilingual post-publish instructions to initialize and validate packages inside an independent consumer directory. Keep versioned package notes, migration guidance and the bilingual static docs site aligned.

## Upgrade and rollback

1. **Plan a cold cache.** Shared BSON query encoding ends at generation `v4`; query/aggregate results, totals and bookmark hashes change. The public bookmark prefix stays `bm:v4`. Refill results and run `prewarmBookmarks()` where needed; old keys may expire normally. No global Redis flush or business-data migration is required. Use broad invalidation or isolated caches while versions coexist; exact descriptors rebuild the current generation.
2. **Version custom cursor restoration.** A custom `cursorValueNormalizer` needs a stable non-empty `cursorValueNormalizerVersion` for page/bookmark reuse. Without it, queries execute but those caches are bypassed, prewarming rejects with `INVALID_ARGUMENT`, and deep jumps may hit `jump.maxHops`.
3. **Check special projection combinations.** Pipeline pagination rejects `$slice`, `$elemMatch` and positional find-only projections with `INVALID_OPERATION`. Ordered ID lookup preserves one native query for supported projections; combinations that cannot retain native identity are rejected. Native `preserveOrder: false` remains available. These are explicit compatibility boundaries, not a promise to support every projection/result-mode combination.
4. **Preserve sync checkpoints before downgrade.** New empty-store sync startup persists an opaque initial envelope with a canonical EJSON Timestamp. Custom stores must round-trip it. Existing raw event tokens stay supported. Stop sync and preserve its store before downgrade: older readers cannot consume the initial envelope as a raw resume token. A saved event token only restores format compatibility subject to history retention and the older version's behavior. Do not erase the envelope or restart from now.
5. **Coordinate sync marker upgrades.** Idempotency keys are v2 JSON tuples. Stop writers, drain work and preserve checkpoints, both marker generations and a recovery snapshot. Avoid mixed-format writers. Ambiguous legacy concatenated markers cannot be trusted unconditionally; use target-owned business idempotence and replay unless a finite mapping is provable. Rollback requires the same stop/drain safeguards, a compatible raw token and a verified target recovery point; never clear either store as a shortcut.

## Compatibility and verification

- MongoDB remains the only complete database adapter. No public method is removed or renamed; default invalidation behavior and the documented checkpoint compatibility boundaries are retained.
- The approved root CJS/ESM budget is 820,000 bytes per artifact; the independent CLI stays at 50,000 bytes. These are build-size gates, not application resource or request limits.
- Qualification uses the existing full tests, coverage and risk floors, runnable examples, Node 20/22 × Driver 6/7 × MongoDB 7/8 matrix, dataTasks/CLI integration, production dependency audit, independent packed CJS/ESM/types/bin consumers and bilingual site/browser/accessibility checks. The release candidate is subject to fresh CI and `release:preflight`; this note alone does not claim they passed.
- Private SSH/Atlas environments remain operator-managed supplemental checks. OIDC readiness does not prove npm-side trusted-publisher configuration; npm validates it during the actual publish.
