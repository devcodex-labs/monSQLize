# monSQLize v3.5.3

> Release date: 2026-11-02
> Publication authority: the immutable tag and npm registry. An untagged checkout is a release candidate; the date above does not establish registry availability.

## Highlights

Patch release with GridFS and Search index fixes found by the 2026-11-02 weekly scan, plus one GridFS contract change: retrying `finalizeResumableUpload` is now idempotent.

## Contract change

- `finalizeResumableUpload` retried while its upload session still exists, for an id whose file is already visible with the same `metadata.sha256` and length as the session, now **returns that committed file and deletes the session** instead of throwing `GRIDFS_FILE_EXISTS`. A visible file with a different sha256 or length still throws `GRIDFS_FILE_EXISTS`. A retry after the session is gone still throws `GRIDFS_FILE_NOT_FOUND`; use `getFile(uploadId)` to check the result. Callers that treated `GRIDFS_FILE_EXISTS` on retry as "already finalized" now receive the file info instead.

## Fixes

- `uploadStream` with an `id` that already has a file now rejects with `GRIDFS_FILE_EXISTS` before writing; a duplicate-key write failure no longer runs cleanup that deleted the original file's chunks and files document.
- `downloadStream` closes the driver stream and its server cursor when the consumer destroys it early; `download` does the same on a read error.
- `appendChunks` that loses a race with `abortResumableUpload` now rejects with `GRIDFS_FILE_NOT_FOUND` and removes the chunks it wrote.
- `drop()` resets the bucket's index latch, so `ensureIndexes()` and later writes on the same bucket object recreate the indexes.
- `uploadStream` failures before the driver stream opens now destroy the returned `Writable` with the mapped error; `upload` with an existing `id` releases a `Readable` source.
- `finalizeResumableUpload` no longer fails after the files document is committed when only the session cleanup fails (logged as a warning; the TTL removes the session); post-insert reads and filename lookups map driver errors. Retrying `finalizeResumableUpload` while the session exists is now idempotent: a visible file with the same id, sha256 and length is returned and the session deleted; a different file still throws `GRIDFS_FILE_EXISTS`, and a retry after the session is gone still throws `GRIDFS_FILE_NOT_FOUND`.
- `abortResumableUpload` deletes leftover chunks even when the session expired; `beginResumableUpload` with a reused explicit `id` clears leftover chunks; `GRIDFS_RESUME_MISMATCH` details report the real `expectedNextChunk`.
- `waitForSearchIndex` arms its deadline in segments, so `timeoutMs` above 2,147,483,647 ms no longer times out after 1 ms.
- `appendChunks` reads only chunks at or after the session's `nextChunk`, restoring a near-constant cost per append (3,000 chunks of 1 KiB on a local memory server: the last 500 appends averaged 16.76 ms before and 3.69 ms after).

## Packaging

The runtime bundle ceilings in `config/package-budget.json` were raised for these fixes. No dependency versions changed.

## Upgrade and rollback

No migration is required. Rolling back to 3.5.2 restores the previous defects, including data loss when `uploadStream` reuses an existing id, and the old `GRIDFS_FILE_EXISTS` result on finalize retries.
